Product notes · implemented vs. proposed

Make it more live, more interactive, simpler

The dashboard already does the basics: live polling, two alert feeds, charts, depth and automatic paper trading. These are the next changes that would most improve the speed and quality of a trader’s decision — ordered by impact, with the honest implementation cost.

LIVE

Event-driven feel without a key

ALERTS

CHART

UI principles to keep

  • Topic first, event second. Keep the five topics separate and group sibling strikes inside their event. Never mix them into one global feed without a label.
  • One decision per screen. The chart, the two feeds and the board answer three different questions; keep them in that order and avoid adding a fourth competing panel.
  • Show the basis. Mid, last, computed and estimated must be visible wherever a number appears.
  • Colour has one meaning. Green/red is direction only; blue is model; amber is a warning; never use colour alone to encode a result.
  • Empty is information. A blank table with a reason beats a plausible-looking placeholder.
  • Every claim is clickable. A row without a source link is a bug.

Data-quality work that pays for itself

  • Persist ticks, not just snapshots. A 7-day rolling Parquet/SQLite store makes replay, backtests and “what happened at 14:32?” possible.
  • Diff the catalog daily. Alert when a topic’s open-market count drops to zero or a series disappears, so coverage gaps are explained rather than discovered.
  • Pin the docs version. Save the API reference date with each snapshot; Kalshi’s API is evolving (the order endpoint is already V2).
  • Test the money paths. Keep the fee example, threshold edge and settlement payout in the unit suite; add a signed demo request test once a key exists.
  • Fail closed. Never deploy a snapshot with zero in-scope markets or a missing source link — the workflow already refuses to publish an empty collection.

Suggested build order

Three short sprints, each ending with something a trader can use.
Sprint 1

Make alerts event-driven

Authenticated WebSocket consumer, SSE to the page, persisted ticks, latency monitor. Closes the polling gap without exposing a key.

Sprint 2

Explain the move

News timeline, trade tape, depth heatmap, replay. Every alert can be opened into a small, source-linked story.

Sprint 3

Let the trader experiment

Strategy lab, watchlists, notifications, focus mode, permalinks. The model becomes a tool the trader controls rather than a fixed feed.

What not to add. A generic “AI prediction” with no inputs, a live P&L number before a fill, a news headline presented as the cause of a move, or a single merged feed across all topics. Each would make the dashboard look smarter while making it less trustworthy.
