⚑ Flagged for Review

Everything irregular, unverified, or assumed during the build — with the source evidence for each. Per the project rules, none of these block the site: they are published here so you can review and request changes after the site is live. Each item lists what was observed, the official source checked, and the action taken (value left blank / flagged / documented as demo behavior).

F1Sandbox network cannot reach Kalshi directly Direct HTTPS from the build sandbox to external-api.demo.kalshi.co fails at TLS (SSL_ERROR_SYSCALL after ClientHello). All data was instead retrieved through the platform's verified page fetcher, which queries the same official endpoints. The build-time snapshot therefore reflects 2026-11-22 ≈07:00–07:20 UTC. API environments (official) Site ships in snapshot + browser-live mode; see F4.
F2No demo API keys in this session Order placement, portfolio and user websocket channels require RSA-signed requests with demo API keys; none exist here. No real trades were and can be executed on the demo account. API Keys (official) · Demo environment (official) Portfolio page runs a clearly-labeled SIMULATED paper engine instead.
F3Demo environment is a sparse subset of Kalshi Verified empty (0 markets) in demo: KXGAS (Gas weekly, EIA), DIESEL, DIESELM (EIA), KXBBMARTIST (Billboard), KXRTFIRSTOMEN (Rotten Tomatoes), KXRIPPLED (Ripple daily). The docs say status values are unopened/open/closed/settled and the filter selects by status — the demo data appears inconsistent (synthetic environment). Get Markets (official) · the observed query Site filters on each record's own status field instead of trusting the query filter.

F10Kalshi website URL pattern not in API docs The official docs don't document the website's /markets/{series}/{slug}/{ticker} pattern. F11Simulated-portfolio numbers are projections Fee model: official quadratic formula 0.07·C·P·(1−P) (the fee schedule PDF referenced by the API's fee_type=quadratic) — applied as an approximation; maker/taker distinctions and rounding not modeled. Sample size is very small (snapshot, not history). Kalshi fee schedule (official) · Fee rounding (official) Portfolio page carries a persistent SIMULATED banner; findings labeled hypotheses.
F12Settlement-timestamp oddities in demo Some demo markets show settlement_ts years after their close (e.g. NOBELLIT-24 close 2024-10-12, settlement 2026-11-05). Consistent with a backfilled synthetic environment; timestamps shown exactly as the API returned them. the observed query Documented; no correction applied (never modify verified data).

Unverified-by-necessity (left blank on data pages)

  • 24h volume for long-dated open markets — most open markets report volume_24h_fp = 0.00; the tables show total volume with an explicit label instead of pretending 24h activity exists.
  • Ask sizes — the orderbook endpoint returns bids only (official design); ask sizes come from the market record's *_ask_size_fp and are often 0/blank in the demo. Shown as "–" when absent.
  • News causation for jumps — specific news articles were not fetched (sandbox network limits); only the official settlement sources are linked as "the place to check the cause".
  • Production (non-demo) volumes — this project targets the demo environment as specified; production figures are intentionally absent rather than estimated.
