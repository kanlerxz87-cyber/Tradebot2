Findings & methodology

What the site measures, how each number is produced, and what is still unverified. Live counts are on the home and dashboard pages.

Executive summary

  • Data source. Public, unauthenticated, read-only Kalshi endpoints (see Sources). Market data comes from the production REST host documented by Kalshi; the demo host is also documented and was used for endpoint checks.
  • Alerts. A market is flagged when its YES last price changes by $0.10 or more between two consecutive collection runs. Each alert links to the API endpoint and the event’s settlement sources.
  • Cause of a move. Not known. The API does not report causes. Settlement sources are listed as reference links only and are marked unverified as causes.
  • High-ROI screen. A fixed, transparent rule set: spread ≤ $0.03, ask size ≥ 50 contracts, 24h volume ≥ 100, entry price between $0.05 and $0.95. It is not a trained or validated model. Its ROI column is a gross proxy, (1 − entry) ÷ entry, before fees.
  • Simulated trades. Paper trades only, 10 contracts each, fees not modelled. Results are for testing the pipeline, not evidence of an edge. Sample size is too small to judge a strategy until several weeks of runs accumulate.
  • Resolutions. Tracked from the API result field (yes/no) on GET /markets/{ticker}.
  • Not done. Demo-account portfolio tracking needs API-key credentials that were not supplied in the chat. Second-level price resolution needs a streaming client (see suggestions).

Verification of this site

  • Every endpoint and parameter named on this site was checked against Kalshi’s official docs pages or OpenAPI file; each check is listed on Sources.
  • Every market row carries a link to the API endpoint that produced it. Values the API did not report are left blank and marked unverified.
  • Repository irregularities are on Repo review.

Methodology

  1. Discover series per topic with GET /series (filters category and tags), ranked by volume_fp, top 40 per topic.
  2. Fetch open events and nested markets with GET /events?series_ticker=…&status=open&with_nested_markets=true.
  3. Store one snapshot per market per run; compare with the previous snapshot; alert at |Δ last| ≥ 0.10.
  4. Sample resting depth for the 25 most active markets with GET /markets/{ticker}/orderbook?depth=10.
  5. Check unresolved markets that have left the open listing with GET /markets/{ticker}, up to 60 per run, and record result.
  6. Open and close paper trades on the YES bid; settle to $1.00 (YES) or $0.00 (NO).

Scheduled job: GitHub Actions, every 15 minutes (cron */15 * * * *). GitHub documents that the schedule event can be delayed under high load, that the shortest interval is 5 minutes, and that scheduled workflows run only on the default branch (source).
