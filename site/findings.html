Findings & methodology

Exactly how each number on this site is produced, and where the method stops being able to answer a question.

Data flow

  1. Discovery. GET /series with the topic's official filter (include_volume=true, up to 200 per page), ranked by volume_fp; top 40 series per topic.
  2. Events and markets. GET /events?series_ticker=…&status=open&with_nested_markets=true for each series.
  3. Publish. Keep markets with 24h volume or open interest, cap per topic by activity, and record the omitted count.
  4. History. GET /series/{series}/markets/{ticker}/candlesticks at 1-minute (6h) and 1-hour (30d) intervals, plus GET /markets/trades (≤1,000 prints, 6h) for the most active markets.
  5. Depth. GET /markets/{ticker}/orderbook?depth=10 for the 25 most active markets.
  6. Alerts. Compare each market's last price with the previous run; |Δ| ≥ $0.10 creates one alert per market per run.
  7. Trades. Screened alerts open paper trades; open trades are marked on the YES bid and closed on target, stop, time stop or settlement.
  8. Resolution. GET /markets/{ticker} for markets that left the open listing; record result.

What the data cannot tell you

  • Why a contract moved. The API reports prices and trades, not causes. Any news headline shown anywhere on this site is a reference link from the event's settlement sources, and is marked unverified as a cause.
  • Sub-interval alert latency on this page: it renders the collector's JSON, not a browser poll. The API itself does allow cross-origin reads for this site's origin (measured, see data/probe.json); WebSocket channels need a signed handshake.
  • True dollar volume. Kalshi publishes volume in contracts, not dollars; the $ columns are explicitly labelled “computed”.
  • Edge. Fees, queuing and slippage are not modelled. Early samples are far too small to judge a strategy.
  • Your demo account balance. Reading it needs signed API requests with stored credentials; none exist in this repo.

Verification performed

Each endpoint was read from docs.kalshi.com and then exercised against the demo host on 2026-11-22; the log of what was checked, with links, is on Sources. The site is checked on every build for broken internal links, for a source link on every table row rendered from static HTML, and for a source URL in every data record (scripts/check_site.py).
