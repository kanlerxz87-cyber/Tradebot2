An alert fires when a contract's last price moves by $0.10 or more in either direction between two collection runs. Chat 1 shows every alert. Chat 2 shows only alerts that pass the high-ROI screen the model likes (tight spread, size at the ask, 24h volume, entry between $0.05 and $0.95).

What the high-ROI screen is — and is not

The screen is a fixed, published rule set evaluated at alert time: spread ≤ $0.03, at least 50 contracts resting at the YES ask, 24h volume ≥ 100 contracts, and entry price between $0.05 and $0.95. The ROI figure shown is a gross proxy, (1 − entry) ÷ entry, before fees. It is not a trained, backtested or validated model, and it does not look at news. Method and limitations →

Why “sudden” is 10-minute granularity. GitHub Actions runs the collector on a schedule, so a $0.10 move is measured between runs, not tick by tick. Kalshi's API also returns no Access-Control-Allow-Origin header (checked 2026-11-22), so a browser cannot poll the API directly from this page. A tick-level alert feed needs a WebSocket client (documented at docs.kalshi.com) running on a server you own. Suggestions →
