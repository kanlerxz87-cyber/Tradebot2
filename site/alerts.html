Live alerting — two scrolling chats

An alert fires when a contract's last price moves by $0.10 or more in either direction between two collection runs. Chat 1 shows every alert. Chat 2 shows only alerts that pass the high-ROI screen the model likes (tight spread, size at the ask, 24h volume, entry between $0.05 and $0.95).

What the high-ROI screen is — and is not

The screen is a fixed, published rule set evaluated at alert time: spread ≤ $0.03, at least 50 contracts resting at the YES ask, 24h volume ≥ 100 contracts, and entry price between $0.05 and $0.95. The ROI figure shown is a gross proxy, (1 − entry) ÷ entry, before fees. It is not a trained, backtested or validated model, and it does not look at news. Method and limitations →

Why “sudden” is the collection interval and not a tick. This page reads the collector's JSON, so a $0.10 move is measured between runs. The demo API does allow browser reads: a probe from this site's own origin (https://kanlerxz87-cyber.github.io) returned Access-Control-Allow-Origin equal to that origin with Access-Control-Allow-Credentials: true, and the OPTIONS preflight returned 204 with the same origin — measured by CI on 2026-11-22 and published in data/probe.json. A per-second alert feed would therefore only need a browser polling loop (or a WebSocket client, which does require a signed handshake — the unauthenticated handshake was rejected with HTTP 401).
