Making the desk more live and more useful

Suggestions are split into what this session actually implemented and what is worth doing next. Each one says what it needs, so a cost is visible before you ask for it.

Implemented in this session

  • Two scrolling chats side by side — every ≥ $0.10 move, and the model's high-ROI subset — with topic filter, auto-scroll and a per-alert link to the exact API response.
  • Real price history instead of snapshots only: Kalshi's 1-minute and 1-hour candlesticks and its sub-second trade tape, so the X axis can be seconds, minutes or hours.
  • Time-range buttons (1h / 6h / 24h / 7d / 30d) that match the available data instead of pretending to have more.
  • Alert markers drawn on the chart, so a price jump and its alert are visible in the same picture.
  • Liquidity ladder with cumulative depth on both book sides, plus “contracts available at the ask” and the computed cost to fill that size.
  • Highest-dollar events ranking (computed 24h notional) with events grouped inside their topic pages.
  • Honest freshness banner — data timestamp, age, environment and a stale warning.
  • One canonical site at the root, one build pipeline, and a source link on every row.

What is deliberately not suggested

  • More aggregate “live” counters that are not backed by a response — the previous builds did that and it was misleading.
  • Filling blank cells with estimates. Blank plus unverified is the rule.
  • Claiming a cause for a price move from the API. It does not publish one.
