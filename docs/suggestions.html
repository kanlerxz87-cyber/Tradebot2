Suggestions

How to make this site more live and more useful, in priority order

Each idea names the API capability it would lean on and what it would take. The first column is effort, the second is what a trader actually gets. Several of these are blocked by constraints that are also listed, so the list stays honest about what is a weekend job and what needs a key.

#ideawhat it changes for the traderAPI capabilityeffort
1 Replace polling with the ticker + trade WebSocket channels. One connection, per-market subscriptions, server pushes every price and volume change. The ≥ $0.10 detector stops depending on an 8-second sample and fires on the actual tick. The chart becomes a true tick stream instead of a polling staircase. ticker, trade, market_lifecycle_v2 channels; handshake needs the same RSA-PSS headers. 10-second idle ping, 429 on connection limits. docs ↗ medium
2 Attach a news/“what moved it” link to each alert. For every alert, show the series' settlement_sources, the market's rules_primary, and a search link built from the event title. A $0.10 jump becomes explainable: the trader sees the resolution source and can jump straight to the outlet that decides it, instead of hunting for a cause. GET /series/{ticker} already returns settlement_sources[] with names and URLs; GET /markets/{ticker} returns the rules text. docs ↗ low
3 Depth-weighted alerts. Weight a move by the contracts available at the touched levels, so a 10-cent move through 5 contracts ranks below the same move through 2 000. Stops the feed from drowning in noise moves that no one could actually trade through. orderbook_delta channel or the REST book; cumulative ladders are already implemented in engine/kalshi.py. docs ↗ low
4 Real candlestick backfill per chart. Load /candlesticks for the selected window so a chart opens with history instead of filling in over time. The 1 h / 4 h / 24 h buttons become instantly useful, and the alert markers overlay real OHLC bars. period_interval 1/60/1440, ≤5 000 periods per request. Implemented and chunked in engine/kalshi.py. docs ↗ low
5 Ladder view per event, not per market. Show the whole strike ladder of an event stacked, so a parallel shift across strikes is visible at a glance. Most real signals are shifts across a ladder, not a single strike. This is how you spot "the whole market repriced" versus "one strike got hit". GET /events?with_nested_markets=true returns every strike in one call. docs ↗ medium
6 Paper-trade straight from the alert. A one-click "take this fill" button that books the trade at the quoted price plus the official taker fee, then tracks it to exit or resolution. Closes the loop between seeing a move and testing a reaction on it, without risking a cent. Reuses engine/paper.py; needs the book at click time to avoid stale fills. fee schedule ↗ medium
7 Resolution watchlist with countdowns. Sort open positions by close_time and flag markets in determined whose settlement timer has not finished. You stop being surprised by a settlement; the countdown tells you when money is about to move. settlement_timer_seconds and the lifecycle statuses are already in every market object. docs ↗ low
8 Compare demo and production side by side. A toggle that reads the same ticker from both hosts so demo drift is visible rather than assumed. Tells you instantly whether a "signal" is real or a demo artefact — the single biggest trap in this repo. Same public endpoints on both hosts; production is read-only here. docs ↗ low
9 Fee-aware P&L everywhere. Show gross and net side by side on every alert and trade, using the published taker/maker rates and each series' fee_multiplier. Trains the right instinct: a 10-cent move is not a 10-cent profit. fee_multiplier and fee_type are per-series fields; the fee formula is published. fee schedule ↗ low
10 Alert the moment a market enters determined. Subscribe to lifecycle events and post "result set: yes/no, settling" into the feeds. Resolution becomes part of the live stream, which is what "track until resolved" should look like. market_lifecycle_v2 emits determined and settled. docs ↗ medium
11 Keyboard-first trader layout. Single-key topic switching, j/k market navigation, space to freeze the feed while you read. Cuts the mouse out of the loop during fast moves. Pure front-end; no API dependency. low
12 Persist the paper portfolio server-side, not in localStorage. Tiny append-only JSON committed by a scheduled job, so results survive a browser change and can be reviewed in git. Portfolio history becomes auditable, and the strategy comparison stops resetting. No Kalshi dependency; needs a scheduled CI job. actions ↗ medium

Deliberately not suggested

  • "AI predicts the winner" panels. Nothing on this site can verify a prediction, and a confident wrong number is worse than a blank cell. The ROI score is published as an explicit formula precisely so it can be argued with.
  • Auto-trading from the alert feeds against production. Requires signed requests from a server you control, a kill switch, and position limits — and the demo's prices are not production's. Not a dashboard feature.
  • Filling chart gaps with interpolation. A flat line across an hour with no trades would imply trading that did not happen.

Constraints that shaped the list

  • WebSocket connections require authentication even for public channels, so a static GitHub Pages site cannot stream directly — a thin relay with a key is required (see WS connection docs ↗).
  • The demo exchange's prices are documented as possibly diverging from production, so anything that looks like a signal needs the production comparison in idea 8 before it is trusted.
  • No credentials exist in this build environment, so every portfolio number on the site is simulated by design.
