Status: needs review — these do not block the dashboard from working.

Read this first — F-01. The repository previously published a root dashboard presenting fabricated Kalshi data as live: tickers that do not exist in the API (e.g. GAS-24DEC-3.15, PRES-24-DJT, OSCAR-BESTPIC-25), invented “catalysts” for price moves, and a portfolio P&L derived from them (“Win rate 75%”, “Sharpe 1.84”). Those pages have been moved to /legacy/ behind a warning banner and are no longer linked from the landing page. The dashboard you are on now reads the live API and shows “—” where data is missing.

F-02 “Gas prices” is a proxy, not retail gasoline The API has no retail-gasoline tag. The topic uses category=Commodities + tags=Oil & Gas, which also returns crude and heating-oil contracts. AAA retail gasoline series do exist in the demo (e.g. KXAAAGASW) but the API does not classify them as retail fuel. get-tags-for-series-categories · get-series-list
F-03 “Culture” is mapped to “Entertainment” No category named “Culture” exists in the verified taxonomy. The site maps the topic to category=Entertainment and says so on the topic page. get-tags-for-series-categories
F-04 No cause data for price moves The API returns prices and trades, not news. The brief asked for “website links that may have caused a jump”. No official field provides this, so the site shows the market, the move and the liquidity context — and deliberately does not assert a cause. Any cause-to-move mapping would be invented, so it is omitted rather than guessed. get-markets · get-trades
F-05 Public REST polling, not a per-second tape Every WebSocket connection requires signed API-key headers, so a key-less static site cannot stream. Alerts therefore compare consecutive refreshes (default 60 s). Moves inside a single minute may not raise an alert; the 1-minute candles show them after the fact. quick_start_websockets
F-06 Demo-account portfolio not connected Reading a Kalshi balance requires signed API keys. No key was provided and none is stored in the repo. The portfolio on this site is a local simulation with a $10,000 starting balance (a simulation assumption, not a Kalshi figure). api_keys · get-balance
F-07 Demo market coverage is partial Kalshi states the demo is for testing and prices may not reflect real markets. Several real series have no demo markets, so a topic can be genuinely empty. Empty states are labelled “no markets returned”, never filled. demo_env
F-08 Event scan is capped GET /events returns at most 200 events per page. The dashboard pages through a fixed number of pages per status to stay responsive; when the cap is hit, a visible “Partial view” banner appears and counts are labelled as lower bounds. get-events
F-09 Old settled markets vanish from live endpoints Markets that settled before the historical cutoff only exist under /historical/*. Resolutions shown here are those still returned by the live endpoints; the site does not claim a complete historical record. historical_data
F-10 Fee model excludes maker fees and slippage Simulated fills pay the taker fee ceil(0.07 × C × P × (1−P)) at the quoted price. Maker fees (0.0175 multiplier where applied) and slippage across a real book are not modelled. Per-series fee multipliers in the published schedule are not applied. fee schedule
F-11 The reversion screen is an unvalidated hypothesis Chat 2’s filter (50% retrace target, costs netted, liquidity gates) is a stated hypothesis, not a validated edge. Its realised performance is published on the portfolio page so it can be judged on evidence. model description
F-12 In-browser history is per-device Price snapshots and alerts are stored in this browser’s localStorage. A different browser or a cleared cache starts empty; alerts begin only after two refreshes have been compared. —
F-13 Sub-cent prices Some markets use deci_cent tick structures. The site keeps 4-decimal precision from the *_dollars fields and displays hundredths of a cent where needed, but a 10¢ alert on such a market is measured on the same 0.01-dollar grid as all others. fixed_point_migration
F-14 Scalar markets are excluded from YES/NO logic The API can return market_type=scalar and a result of scalar. Resolution tables show those as blank rather than forcing them into a YES/NO column. get-markets
F-15 Retired documentation URL in README The README badge and table link to trading-api.kalshi.com/trade-api/v2/documentation, which the current documentation does not list among its supported environments. The live pages use only the documented hosts. api_environments

What “unverified” means here

  • A table cell shows “—” when the API did not return that field. It is never back-filled from a similar market, a guess, or an example.
  • Notional is shown as contracts × the API's notional_value_dollars (which is $1.00 for every verified binary market here); it is not a P&L figure.
  • “Highest-dollar” ranking uses traded notional, not open interest, because the brief asked about the size of the event. Both figures are in the tables.
