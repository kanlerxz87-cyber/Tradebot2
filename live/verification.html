3. The one thing this site cannot show: your demo-account balance

Reading a Kalshi portfolio requires a signed request with an API key. The documented flow is:

  1. Create a demo account and an API key pair (Ed25519 is recommended; RSA-PSS also supported).
  2. Sign timestamp + method + path — path without the query string.
  3. Send KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP (ms, within 30 s of Kalshi's clock) and KALSHI-ACCESS-SIGNATURE.
  4. Call GET /portfolio/balance and GET /portfolio/positions.

No key is stored in this repository, and no key was provided in the session that built it, so the portfolio on this site is a local simulation. This is flagged as F-06. The design keeps that honest: every simulated trade is labelled, and nothing claims to be a Kalshi balance.

5. How the site was tested

  • 76 automated checks run headlessly (jsdom) against recorded responses that follow the official schemas: parsing, the exact $0.10 alert boundary in both directions, topic joins, aggregation ordering, order-book math, paper-trade accounting and rendered-page assertions.
  • Fee maths is checked against the published fee table: 100 contracts at 50¢ must cost $1.75, and 1 contract at 10¢ $0.01.
  • Link check across every page and asset, plus a check that no fabricated ticker appears anywhere.
  • No network stubs on the live site. The test fixtures live under live/tests/ and are never loaded by a page.
